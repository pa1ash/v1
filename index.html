Зачем нужна единая система

Устранение разночтений в отчётности смежных подразделений и создание прозрачной среды для всех участников процесса

📋

Систематизация учёта данных

Все данные по проектам структурированы и хранятся в единой системе. Исключается дублирование и потеря информации между подразделениями.

🌐

Единое информационное пространство

Все подразделения работают в одной среде с актуальными данными. Нет расхождений между отчётами — все видят одну «правду».

📊

Единая отчётность

Консолидированные отчёты формируются автоматически. Руководящий состав получает целостную картину по всем проектам компании.

🏷️ Стандарт наименований

Единая кодификация проектов

Единый регламент наименования гарантирует однозначное распознавание проектов во всех подразделениях

Почему это критически важно

Приказ о нейминге был создан из-за разночтений проектов в отчётах смежных подразделений. Руководящий состав столкнулся с ситуацией, когда один и тот же проект фигурировал под разными названиями в разных отчётах.

Единая кодификация исключает эту проблему: каждый проект получает уникальный, стандартизированный идентификатор, используемый во всех подразделениях и отчётах.

⚠️
Требуется актуализация Приказ о нейминге хранится: L:\Регламенты — подписанная версия не найдена. Рекомендуется актуализировать и переподписать при отсутствии возражений.
ℹ️
Предпосылка создания Приказ родился из-за непонимания руководящего состава при разночтении проектов в отчётах смежных подразделений.

🔄 Жизненный цикл проекта

Три стадии проекта

Каждый проект проходит полный жизненный цикл с наследованием данных между стадиями

1

🚀 Пресейл

Инициация проекта. Создание пресейл-активности запускает автоматическое формирование связанных сущностей.

  • ⚡ Автосоздание сущности Экономика
  • 📦 Автосоздание сущности Логистика
  • 📑 Автосоздание сущности Торги
  • 🔔 Уведомление ФД о новом проекте
  • 📊 Плановые показатели и оценки
→
2

⚙️ Реализация

Наследование всех сущностей из Пресейла. Плановые показатели становятся фактическими.

  • 🔄 Наследование всех сущностей Пресейла
  • 📈 План → Факт по всем показателям
  • 💰 Фактические затраты и оплаты
  • 🚚 Фактическая логистика и доставка
  • 📋 Трансляция данных в отчётность
→
3

✅ Гарантия

Закрывающий этап: сверка расчётов, проверка документов и постановка на гарантийный учёт.

  • 🔍 Сверка всех расчётов по проекту
  • 📄 Проверка документации проекта
  • 🛡️ Постановка на гарантийный учёт
  • 📦 Сверка серийных номеров (пакинги)
  • ✔️ Финализация экономики проекта
